90분 수업은 이렇게 진행해요

차시·시간학생 활동교사 확인
1차시 0~5분완성 예시와 오늘의 목표 확인계정·개인정보 안전 안내
1차시 5~15분바이브 코딩과 GitHub 연결·권한 이해수업용 저장소만 쓰기 권한 연결
1차시 15~30분활동지에 홈페이지 구상과 요청문 작성대상·내용·분위기·조건 확인
1차시 30~45분AI에게 홈페이지를 만들고 저장소에 반영해 달라고 요청실제 페이지 미리보기로 첫 결과 확인
2차시 0~15분페이지를 보며 말로 2~3회 개선 요청AI가 바꾼 내용과 화면 결과 확인
2차시 15~30분AI에게 수정 사항을 저장소에 직접 반영하고 커밋하도록 요청변경 요약과 커밋/PR 결과 확인
2차시 30~40분필요하면 변경을 병합하고 Pages 주소 확인공개 가능한 계정·저장소만 사용
2차시 40~45분짝 피드백과 자기 평가공유 전 개인정보 재점검

만 13세 미만이거나 학생 계정 사용이 허용되지 않은 경우 개인 계정으로 접속하지 않습니다. 교사 시연과 모둠 활동으로 참여하고 공개 배포는 교사가 담당합니다.

계정 승인이나 배포가 지연되면 모든 학생의 공개 완료를 목표로 하지 말고, 교사 시연용 저장소에서 결과를 확인한 뒤 다음 시간에 이어 가세요.
개념

바이브 코딩이란?

🗣 말하기

만들고 싶은 모습을 우리말로 자세히 설명한다.

🤖 만들기

AI가 만든 결과는 틀릴 수 있어요. 반드시 내 눈으로 확인하고, 모르는 부분은 설명해 달라고 요청해요.

코딩 지식이 없어도 시작할 수 있다는 점을 강조하되, 결과를 검증하는 습관이 핵심 역량임을 짚어 주세요.

내 홈페이지

쓰기 작업을 지원하는 GitHub 연결 도구를 사용하면 AI에게 말로 요청해 파일 수정·커밋·병합까지 진행할 수 있어요. 학생은 코드를 직접 편집하는 대신 바뀐 홈페이지를 보고 다시 요청합니다.

연결 도구마다 권한이 달라요. 읽기 전용 연결에서는 직접 저장할 수 없고, 저장소 쓰기 권한과 커밋 기능이 있는 연결에서만 자동 반영이 가능합니다.

학생에게 코드 편집을 시키기보다, 원하는 결과 설명 → AI의 저장소 반영 → 실제 페이지 확인 → 추가 요청의 반복을 경험하게 하세요.
1단계

GitHub 저장소 만들고 Pages 켜기

순서할 일
1GitHub에 로그인 → 오른쪽 위 + → New repository
2저장소 이름은 GitHub 아이디와 똑같이 아이디.github.io로 입력 (예: bluebird27.github.io)
3Public 선택, Add a README file 체크 → Create repository
4Settings → Pages → Source: Deploy from a branch → Branch: main, 폴더 / (root) → Save
5입구 파일은 저장소 맨 위 폴더의 index.html

화면 글자는 한국어/영어로 다르게 보일 수 있어요. 참고: GitHub Pages 공식 문서 (docs.github.com, pages.github.com)

학생 계정은 만 13세 이상이며 학교·보호자 지침에 따라 허용된 경우에만 사용합니다. 그 외 학생은 교사 시연용 저장소로 활동합니다.

저장소 이름이 GitHub 아이디.github.io와 정확히 같으면 홈페이지 주소가 https://아이디.github.io/로 가장 짧아집니다. 아이디 자체가 공개되므로 실명·학교명·생년월일이 드러나는 아이디는 피하세요. 계정마다 사용자 홈페이지 저장소는 하나만 만들 수 있습니다.
2단계

ChatGPT에 GitHub 연결하기

  1. ChatGPT의 설정 → 앱 또는 플러그인에서 GitHub를 찾아 연결해요. 메뉴 이름은 계정과 화면에 따라 다를 수 있어요.
  2. GitHub로 이동하면 로그인하고 ChatGPT 앱 설치·권한 요청 내용을 확인한 뒤 승인해요.
  3. ChatGPT가 볼 수 있는 저장소를 직접 고릅니다 (다음 쪽 참고).
  4. 대화에서 + 또는 @ 메뉴로 GitHub를 선택할 수 있으면 선택하고, 「내 저장소의 index.html을 찾아 어떤 내용인지 요약해 줘」라고 요청해 확인해요.

연결 메뉴와 권한은 계정·워크스페이스·연결 방식에 따라 달라질 수 있어요. 수업 전에 실제로 파일 수정과 커밋을 지원하는지 교사가 확인하세요.

쓰기 권한이 있는 GitHub 작업 도구라면 AI가 저장소 파일을 직접 수정하고 커밋하거나 변경 제안(PR)을 만들 수 있습니다. 읽기 전용 GitHub 앱만 연결된 경우에는 직접 저장할 수 없으므로 교사 시연용 쓰기 도구를 사용하거나 교사가 대신 반영합니다.
안전하게

연결 권한은 꼭 필요한 만큼만

✅ 이렇게

  • 접근 저장소는 선택한 저장소만(Only select repositories)
  • 아이디.github.io 수업용 저장소 하나만 고르기
  • 쓰기 권한은 파일 수정·커밋에 필요한 범위만 허용

⚠ 이렇게는 안 돼요

  • 모든 저장소(All repositories) 허용
  • 비밀번호·키·학생 정보가 든 저장소를 연결
  • 모르는 사이트에 GitHub 로그인

수업용 저장소 하나만 선택하세요. 쓰기 권한을 허용하기 전에는 저장소 이름과 권한 범위를 반드시 확인하고, 수업이 끝나면 불필요한 연결 권한을 해제하세요.

이 쪽은 시간을 충분히 쓰세요. 학생이 허용 화면을 대충 넘기지 않도록, 저장소 선택 화면에서 한 번 멈추고 모둠별로 확인하게 합니다.
3단계

좋은 설명(프롬프트) 만들기

누가 볼까 + 무엇을 담을까 + 어떤 분위기 + 지켜야 할 조건 을 함께 말해요.

나는 중학교 과학 시간에 만든 발표를 소개하는 홈페이지가 필요해. - 보는 사람: 친구들과 선생님 - 구성: 제목 영역, 내 소개, 좋아하는 과학 주제 카드 3개, 응원 한마디 영역 - 분위기: 밝은 파스텔 색, 둥근 모서리 - 조건: index.html 한 파일, 외부 라이브러리 없이, 휴대폰에서도 잘 보이게 - 마지막에 내가 글자를 바꿀 수 있는 부분을 알려 줘.
학생에게 먼저 자기 설명을 써 보게 한 뒤, 이 예시와 견주어 빠진 항목을 찾게 하면 좋습니다.
4단계

한 번에 하나씩 고쳐 달라고 해요

이럴 때이렇게 말해요
글자가 작아요「본문 글자를 지금보다 1.3배 크게 해 줘」
색이 마음에 안 들어요「배경은 연한 하늘색, 제목은 진한 남색으로 바꿔 줘」
휴대폰에서 깨져요「폭 360px 휴대폰 화면에서도 가로로 밀리지 않게 해 줘」
코드를 모르겠어요「이 부분이 무슨 일을 하는지 중학생에게 설명해 줘」

확인 체크: 휴대폰에서도 보이나요? 글자가 읽기 쉬운가요? 링크가 눌리나요? 내 정보가 너무 많이 드러나지 않나요?

여러 가지를 한꺼번에 요청하면 무엇이 바뀌었는지 알기 어렵습니다. 한 번에 하나, 바뀐 것 확인, 다음 요청의 리듬을 강조하세요.

4. 웹페이지 확인
내 GitHub 저장소 아이디.github.io에 나만의 과학 홈페이지를 만들어 줘. 첫 화면에 제목과 소개를 넣고, 좋아하는 과학 주제 카드 3개를 만들어 줘. 밝고 읽기 쉬운 디자인으로 휴대전화에서도 잘 보이게 해 줘. 코드를 채팅에 길게 보여 주지 말고 저장소 파일에 직접 반영해 줘. 변경 내용을 저장하고 커밋한 뒤, 결과와 홈페이지 주소를 알려 줘.
  1. AI가 만든 홈페이지를 실제 웹페이지로 열어 확인해요.
  2. 「제목 글자를 더 크게 해 줘」처럼 말로 수정 요청을 해요.
  3. AI가 수정 내용을 저장소에 반영하고 커밋했는지 확인해요. 변경 제안(PR)이 만들어졌다면 내용을 확인하고 병합해요.
  4. Pages 배포가 끝날 때까지 기다린 뒤 https://아이디.github.io/를 열어 확인해요. 최대 약 10분 걸릴 수 있어요.

핵심은 코드를 직접 편집하는 것이 아니라, 원하는 결과를 설명하고 실제 홈페이지를 보며 개선하는 거예요.

이 방법은 저장소 파일 수정과 커밋을 지원하는 GitHub 연결 도구에서만 가능합니다. 읽기 전용 연결이면 교사가 쓰기 기능을 시연하거나 별도 저장 과정을 도와주세요. 학생에게는 수업용 저장소 하나만 연결하고, 변경 전후 화면과 AI의 작업 결과를 확인하게 하세요.

교사 시연에서는 실제로 저장소에 반영되는 순간을 보여 주세요. 수업용 저장소는 다른 프로젝트와 분리하고, AI가 수정하기 전에 변경 대상 파일과 요청 내용을 확인하도록 합니다. 학생이 코드를 읽지 않아도 되지만, 공개될 화면과 개인정보는 반드시 확인해야 합니다.
